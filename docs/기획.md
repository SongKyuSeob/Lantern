# 에이전트용 깨어 있기 + 할 일 패널 Mac 메뉴바 앱

작성: 2026-10-22 · 상태: 기획 중, 착수 전
이전 문서: `2026-10-18_구직용_Mac앱_구상.md` (구직 기능은 별도 앱으로 분리하면서 이 문서로 방향이 바뀜)

## 한 줄 정의
에이전트를 돌려 두고 자리를 비워도, 맥은 일이 끝날 때까지 깨어 있고 할 일은 항상 눈앞에 있는 메뉴바 앱.

## 대상
- 취준생: 에이전트로 작업을 돌려 두는 사람
- 에이전트를 자주 쓰는 직장인: 주로 **개인 Mac이나 보안 정책이 없는 소규모 회사 Mac** (MDM이 걸린 회사 Mac은 주 대상 아님)
- 첫 사용자이자 테스터: 실제로 필요하다고 한 친구

## 정한 것
### 앱 분리
- **이 앱**: 깨어 있기(잠자기 방지) + 항상 위 할 일 패널
- **별도 앱**: 지원 내역 관리 + 공고 수집. 친구의 Supabase(웹 + 크롬 익스텐션)와 데이터 공유. 친구 쪽 메인은 지원 내역 관리이고, 공고 수집은 그다음.

### 배포
- Apple Developer 멤버십이 없음 → App Store, Developer ID 공증 모두 불가.
- **GitHub 오픈소스 + Releases(zip)로 배포.** Xcode Archive로 뽑아 임시(ad-hoc) 서명은 들어가게 함.
- 처음 실행할 때 Gatekeeper 경고가 뜸 → README에 안내:
  - 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기" → 비밀번호 → 다시 "그래도 열기" (처음 한 번만)
  - 또는 `xattr -d com.apple.quarantine /Applications/앱이름.app`
- 서명이 아예 없으면 "손상되었기 때문에 열 수 없습니다"가 뜰 수 있으니 반드시 Xcode로 빌드.

### 깨어 있기 구조: "세션 + 옵션 두 개"
- **세션** = 깨어 있기를 켠 순간부터 꺼지는 순간까지의 한 번 (화면에는 "깨어 있는 중 · 1:42 남음"처럼만 보이면 됨)
- **옵션 1. 언제까지**: 계속 / 1시간 / 2시간 / 직접 지정 / 에이전트가 끝날 때까지
- **옵션 2. 뚜껑 닫아도 유지**: 세션 안에서만 켤 수 있음
- 규칙
  - 시간이나 조건이 끝나면 세션 종료 → 깨어 있기와 뚜껑 모드 **둘 다 꺼짐**
  - 뚜껑 모드는 세션 안에서 따로 켰다 껐다 할 수 있고, 꺼도 남은 시간은 이어짐
  - 뚜껑 모드가 켜져 있을 때도 깨어 있기는 항상 같이 켜 둠 → 뚜껑 모드가 풀려도 바로 잠들지 않고 깨어 있기로 내려옴 (뚜껑이 닫혀 있었다면 그때는 잠듦: 의도한 안전장치)
  - 끌 때는 뚜껑 모드부터 끄고, 그다음 깨어 있기
- 슬라이더(끔/깨어 있기/뚜껑)나 별도 토글 두 개는 쓰지 않기로 함
  - 슬라이더: 시간이 붙으면 "몇 칸 내려가는지, 타이머가 이어지는지"가 애매함
  - 별도 토글: "뚜껑만 켜고 깨어 있기는 꺼짐" 같은 말이 안 되는 조합이 생김

### 메뉴바 드롭다운 (초안)
```
● 깨어 있는 중 · 1:42 남음      [지금 끄기]
언제까지: 계속 / 1시간 / 2시간 / 직접 / 에이전트가 끝날 때까지 ▸
☑ 뚜껑 닫아도 유지 🔒   지금 닫으면: 유지됨
화면만 끄기 · 할 일 패널 ☑ · 설정
```
- 권한이 없으면 뚜껑 옵션에 자물쇠 표시 → 누르면 설치 안내 (숨기지 않음)
- "지금 닫으면: 유지됨 / 잠듦"은 전원, 외장 모니터, 뚜껑 모드 여부로 판단

### 두 장치의 기술적 차이
| | 깨어 있기 | 뚜껑 닫아도 유지 |
|---|---|---|
| 방식 | IOPMAssertion (caffeinate와 같음) | `pmset -a disablesleep 1` |
| 막는 것 | 가만히 둬서 잠드는 것 | 뚜껑 닫힘 + 가만히 둬서 잠드는 것 + 애플 메뉴 "잠자기"까지 전부 |
| 권한 | 없음 | 관리자 (처음 1회) |
| 앱이 죽으면 | macOS가 자동으로 해제 | **설정이 그대로 남음** → 원복 장치 필요 |

### 뚜껑을 닫았을 때 (macOS 기본 동작, 클램쉘 모드)
| 상황 | 뚜껑을 닫으면 |
|---|---|
| 아무것도 연결 안 함 | 잠듦 |
| 전원만 | 잠듦 |
| 전원 + 외장 모니터 | 안 잠듦 (단, 가만히 두면 잠드는 건 여전히 일어남 → 깨어 있기 필요) |
| 외장 모니터만 (배터리) | 잠듦 |
- 외장 모니터를 버튼으로 끈 경우: 대부분 연결이 유지돼서 안 잠듦. 일부 모니터, USB-C 연결, 절전 옵션이 켜진 모니터는 연결이 끊겨 잠들 수 있음.
- 멀티탭으로 전원을 끊으면 거의 확실히 잠듦.
- 확실한 방법: 모니터를 끄지 말고 **디스플레이 잠자기**(`pmset displaysleepnow`) 사용 → 앱에 "화면만 끄기" 버튼으로 넣음.

## 주의해야 할 것
### 뚜껑 모드
- **설정이 영구적**: 앱이 꺼지거나 죽어도 `disablesleep 1`이 남음.
  - 감시 프로세스(launchd 사용자 에이전트, 관리자 권한 불필요)가 앱이 사라진 걸 감지하면 원복
  - 앱을 실행할 때마다 현재 상태를 점검
- **애플 메뉴의 "잠자기"도 안 먹음** → 앱의 잠자기 버튼은 `disablesleep 0` 후 `pmset sleepnow`
- **발열**: `ProcessInfo.thermalState`가 `.serious` 이상이면 뚜껑 모드 자동 해제
- **배터리**: 기본은 전원 연결 시에만. 배터리일 때는 일정 % 이하에서 자동 해제. 전원이 빠지면 해제할지도 선택
- 자동 해제가 일어나면 이유를 알림으로 보여 줌 ("발열 때문에 뚜껑 닫기 유지를 껐어요")
- 예상치 못하게 잠들었다면 깨어난 뒤 원인 안내 ("모니터 연결이 끊겨서 ○시 ○분에 잠들었어요")
- `disablesleep`은 문서화되지 않은 옵션 → 착수 전에 macOS 26에서 동작하는지 직접 확인:
  ```bash
  sudo pmset -a disablesleep 1
  while true; do date >> ~/awake.log; sleep 10; done   # 뚜껑 몇 분 닫았다 열고 로그가 이어지는지 확인
  sudo pmset -a disablesleep 0
  ```

### sudoers 규칙 (뚜껑 모드 권한)
- 처음 한 번 관리자 비밀번호로 `/etc/sudoers.d/`에 규칙 설치, 이후 앱은 `sudo -n pmset ...`만 호출
- 루트 헬퍼(`SMAppService.daemon`)는 서명이 제대로 안 된 앱에서 불안정할 수 있어서 이 방식을 씀
- 규칙은 **그 사용자 계정의 모든 프로그램**(다른 앱, 스크립트, 에이전트)이 쓸 수 있음 → 범위가 곧 위험도
- **인자까지 정확히 쓴 명령 3개만** 허용:
  - `/usr/bin/pmset -a disablesleep 0`
  - `/usr/bin/pmset -a disablesleep 1`
  - `/usr/bin/pmset sleepnow`
- **사용자가 수정할 수 있는 스크립트 경로는 절대 허용하지 않음** → 내용을 바꿔치기하면 루트 권한을 통째로 넘겨줌
- 설치 전 `visudo -c -f 파일`로 문법 검사를 통과한 경우에만 넣음 (문법 오류가 있으면 sudo가 통째로 고장 남)
- 설정 창에 규칙 제거(원복) 기능도 둠

### 공개 저장소
- service_role 키, API 키는 절대 커밋하지 않음 → `Secrets.xcconfig`를 `.gitignore`에 넣고 `Secrets.example.xcconfig`만 올림
- 한 번 커밋된 키는 지워도 기록에 남음 → 바로 폐기하고 재발급
- GitHub 2단계 인증 켜기 (계정이 털리면 Releases 파일이 바꿔치기될 수 있음)
- 릴리스마다 SHA-256 체크섬 같이 게시

## 향후 고려: 모바일(iOS) 앱과 연동
지금 만들지는 않지만, 나중에 iOS 앱을 만들 때 연동할 수 있게 염두에 둠.
**시점: Apple 유료 멤버십을 산 뒤에 검토.** 그 전까지는 Mac 앱만 만듦.

### 연동하면 좋을 것
- **할 일**: 미리 알림(EventKit)으로 가면 iCloud로 iPhone과 이미 동기화됨 → 연동 비용이 거의 없음. 4번 결정에서 미리 알림 쪽으로 기우는 근거
- **세션 상태 알림**: "에이전트 작업 끝남", "발열 때문에 뚜껑 모드 해제" 같은 알림을 iPhone으로 받기
- **원격 조작**: 밖에서 세션 연장 / 지금 끄기 / 잠재우기

### 걸리는 점
- 멤버십이 생기면 CloudKit, 푸시 알림(APNs)을 쓸 수 있어서 별도 서버 없이 연동 가능. 이 경로를 기본으로 검토
- 원격 조작은 **밖에서 내 맥을 제어하는 기능**이라 인증과 허용 동작 범위를 따로 설계해야 함 (뚜껑 모드 켜기는 원격 허용 안 하는 쪽 고려)

### 데이터 저장 원칙: 서버 없이, 사용자 본인 소유
- 데이터는 사용자 기기(로컬)나 사용자 본인 계정(미리 알림, iCloud)에만 둠. **개발자가 운영하는 서버(Supabase 등)는 쓰지 않음**
  - 이유: 내 계정에 문제가 생기거나 서버를 내리면 다른 사람의 데이터까지 같이 사라짐 → 의존 방향이 잘못됨
- 지금(Mac 앱만): 세션 기록은 **SwiftData (확정, 2026-10-22)**, 설정은 `UserDefaults`, 할 일은 미리 알림
  - Core Data는 같은 엔진이지만 스레드 규칙·장황함 때문에, Realm은 동기화 서비스 종료로 제외
- 나중(iOS 연동): SwiftData + CloudKit private database → 각 사용자의 iCloud를 통해 동기화. 개발자는 사용자 데이터를 보거나 지울 수 없음
  - 멤버십이 끝났을 때 동기화가 어떻게 되는지는 그 시점에 확인 필요

### 지금 Mac 앱에서 미리 지켜 둘 것
- SwiftData 모델은 나중에 CloudKit 동기화를 켤 수 있게: 모든 속성에 기본값 또는 옵셔널, 유니크 제약(`@Attribute(.unique)`) 쓰지 않음, 관계는 옵셔널
- 세션, 전원 판단, 할 일 모델 같은 로직은 UI와 분리한 로컬 Swift Package에 둠 → iOS 앱에서 그대로 재사용 가능하게. AppKit 의존은 앱 타깃에만
- 세션 상태와 기록은 `Codable` 모델로 → 나중에 서버나 다른 기기로 보내기 쉽게
- 할 일 저장소는 프로토콜 뒤에 숨김 → 미리 알림 외의 저장소로 바꾸거나 추가하기 쉽게

## 아직 정하지 않은 것
1. 에이전트 감지 방식: 알려진 이름(claude, codex 등) 자동 감지 + 직접 지정 (추천). 친구가 쓰는 에이전트 확인 필요
2. 세션이 끝난 뒤 동작: 깨어 있기만 해제 / 바로 잠자기까지 (사용자 선택, 기본값은 "해제만" 추천)
3. 깨어 있기 중 화면도 켜 둘지 (기본은 화면은 꺼지고 시스템만 깨어 있게 추천)
4. 할 일 데이터를 미리 알림 연동으로 확정할지
5. 최소 macOS 버전 (Foundation Models가 빠져서 26일 필요가 줄어듦. 14 정도 검토)
6. 앱 이름
