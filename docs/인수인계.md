# 랜턴(Lantern) 인수인계

작성: 2026-10-23 · 마지막 갱신: 2026-10-29
상세 기획: `docs/private/기획.md` (2026-10-22 결정 문서 사본, 저장소에는 올리지 않음). **아래 "최신 결정"이 기획 문서보다 우선한다.**

## 한 줄 정의
에이전트를 돌려 두고 자리를 비워도 맥은 일이 끝날 때까지 깨어 있고, 할 일은 화면 우측 상단에 걸어 둔 작은 창에 항상 떠 있는 macOS 앱.

## 화면 (기획 문서의 "메뉴바 드롭다운이 메인"은 폐기)
- **메인은 우측 상단에 떠 있는 작은 창**: 테두리 없는 `NSPanel` + SwiftUI. `level = .floating`, `.nonactivatingPanel`, `.canJoinAllSpaces`/`.fullScreenAuxiliary`, `hidesOnDeactivate = false`
- **평소 상태**: Liquid Glass(`glassEffect`, 섞는 색 없음), 글자는 그림자로 선명하게, 클릭은 뒤로 통과(`ignoresMouseEvents = true`). 활성 창도 Liquid Glass에 검정 12%만 섞음. 창 그림자는 유리 모서리 밖으로 네모나게 잡혀 끔. 투명도 슬라이더는 아직 없음
- 평소 창 위에 커서를 올리면 불투명도 0.12로 흐려져 뒤가 보이고, 벗어나면 돌아옴(2026-10-29). 다른 앱으로 가는 마우스 이동을 전역 모니터로 보고, 흐려진 동안에는 0.1초마다 커서 위치를 직접 확인(순간 이동 시 마지막 알림이 안 올 수 있어서)
- 숨기기 단축키 ⌃⌥⇧L(⌃⌥L에 ⇧만 더함, ⌃⌥H는 JetBrains 호출 계층과 겹침): 평소 창 숨기기 ↔ 보이기. 설정 "단축키"에서 동작별로 바꾸기·끄기, 두 동작에 같은 조합은 못 씀
- 평소 창 모양은 둘: 펼친 모양(깨어 있기 줄 + 할 일 위에서 3개 + "⋯ n more") / 접힌 바(한 줄 + "할 일 n"). 어느 쪽인지는 활성 창의 ⌃/⌄로 정하고 저장됨. 할 일 표시는 탭과 무관
- **활성 상태**: 메뉴바 아이콘 왼쪽 클릭 → 불투명, 조작 가능. 평소↔활성은 전환 효과 없이 한 번에 바뀜(2026-10-26: 내용 페이드는 창 크기가 먼저 바뀌어 잠깐 안 보이는 깜빡임을 만들어 뺌)
  - 평소로 복귀: 아이콘 다시 클릭 / 창 밖 클릭(`NSEvent.addGlobalMonitorForEvents`) / 10초 무조작 (입력 중 제외)
  - 전역 단축키로도 전환(2026-10-26): 기본 ⌃⌥L(앱들이 잘 안 쓰는 ⌃⌥ + Lantern의 L. ⌥⌘K는 Xcode ⇧⌘K와 헷갈리고 ⌥⌘L은 Finder·Safari 다운로드와 겹침). 설정 창에서 바꾸기·끄기·기본값. Carbon `RegisterEventHotKey`라 손쉬운 사용 권한 불필요, ⌘⌥⌃ 중 하나는 꼭 포함. 메뉴바 아이콘이 노치에 가려질 때 창을 여는 수단. "마우스 올리면 활성화"는 설정 옵션 (0.25초 머무름, 0.5초 유예)
- **메뉴바 아이콘**: `MenuBarExtra`가 아니라 `NSStatusItem` 직접 사용. 오른쪽 클릭 = 메뉴(2시간 깨어 있기, 창 숨기기, 설정, 종료). 아이콘 모양으로 상태 표시(꺼짐 / 깨어 있음 / 뚜껑 모드)
- 창 안: 깨어 있기 상태·남은 시간, 언제까지, 뚜껑 모드, "지금 닫으면 유지됨/잠듦", 에이전트 상태, 오늘 할 일. 접으면 한 줄("깨어 있는 중 · 1:42 · 할 일 3")
- M1 구현에서 정한 세부 동작
  - "언제까지" 세그먼트는 메뉴처럼 **고르면 바로 시작**. "시각"은 시각 입력 줄을 열고 "시작"을 눌러야 시작
  - 접기는 평소 상태의 모습만 정함. 활성 창의 ⌃(접어 두기)·⌄(펼쳐 두기)를 누르면 바로 평소로 돌아가 바뀐 모습을 보여 줌(펼치기만 하고 활성으로 남으면 눌러도 변화가 안 보여서). 아이콘 클릭으로 활성이 되면 접어 뒀어도 전체 창. 접힘 여부와 마지막 탭은 UserDefaults에 저장
  - Esc도 평소 상태로 복귀(시각 입력 중 제외). 마우스가 창 위에 있으면 10초 무조작으로 치지 않음
  - 활성 상태에서만 창이 키 입력을 받고, 평소로 돌아가면 키 입력을 원래 앱에 돌려줌(창을 잠깐 내렸다 올림. `animationBehavior = .none`이 아니면 0.3초 페이드가 재생돼 꺼졌다 뜨는 것처럼 보임)
  - 평소 요약·접힌 바는 항상 창 폭을 가득 채움(내용이 짧으면 글자 길이만큼 줄어드는 버그가 있었음)
  - "시각" 입력은 macOS 기본 시각 칸이 글자에 비해 빠듯해서 시·분을 각각 목록에서 고르는 칸으로 바꿈(분은 5분 단위)
  - 시연 모드(디버그 빌드 전용): `open --env LANTERN_DEMO=1 <Debug/Lantern.app>`로 켜면 실제 저장 파일 대신 메모리에 예시 할 일·기록(약 300일)을 채운 저장소를 쓰고, 활성 창이 10초 무조작·바깥 클릭으로 닫히지 않음(`DemoData.swift`). README 캡처(`docs/screenshots/`)를 이걸로 찍음. 실제 데이터에 흔적이 남지 않음
  - 디버그 빌드에만 `com.songkyuseob.lantern.debug` 분산 알림으로 창 동작을 흉내 내고 화면을 저장할 수 있음: `toggle`·`chevron`·`outside`·`pickTime`, `snapshot:<경로>`(플로팅 창 PNG), `settings:<general|agents|power>`(설정 창 열기), `settingsSnapshot:<경로>`(설정 창 PNG). 화면 녹화 권한 없이 모양·위치를 확인할 때 씀
- 설정 창 (2026-10-26): 일반(로그인할 때 열기·단축키) / 에이전트 / 전원(배터리·뚜껑 모드) 세그먼트 탭, 탭 안은 스크롤, 높이 조절 가능(폭 480 고정). 기본 TabView는 테두리가 창 가장자리와 어긋나 쓰지 않음. 메뉴바 앱은 macOS 14부터 `NSApp.activate()`가 거절될 수 있어 `orderFrontRegardless()`로 맨 앞에 띄움
  - "뚜껑 닫아도 유지" 스위치는 M2에서 "지금 뚜껑을 닫으면" 아래에 붙임(권한이 없으면 🔒 설정, 메뉴에도 같은 항목). "연장 ›"은 아직. 할 일 탭은 M4 전까지 자리만 있고, 그 전까지 기본 탭은 깨어 있기
  - 메뉴바 메뉴의 "지금 닫으면" 줄은 창으로 옮김. 메뉴에는 "시각…"(창을 열어 시각 입력)과 "창 숨기기/보이기"
  - Figma는 "랜턴 · 확정 디자인" 섹션 하나만 남기고 나머지 시안은 삭제(2026-10-24)

## 깨어 있기 구조 (확정)
- 세션 하나 + 옵션 두 개: **언제까지**(계속/1·2시간/직접/에이전트가 끝날 때까지), **뚜껑 닫아도 유지**(세션 안에서만)
- 세션이 끝나면 둘 다 꺼짐(뚜껑 모드를 먼저 끔)
- 안전장치 (2026-10-26)
  - 배터리 기준: 충전기 없이 기준 %에 **닿는 순간 한 번** 깨어 있기를 통째로 끔. 그 뒤 사용자가 다시 켜면 그 선택을 따름(충전기를 꽂거나 기준보다 올라가면 다시 동작). 단 기준 아래에서 뚜껑 모드는 못 켬
  - 발열: 뚜껑 모드 중 `thermalState`가 `.serious` 이상이면 **뚜껑 모드만** 끄고 깨어 있기는 유지. 뚜껑을 열어 둔 상태의 발열은 macOS 기본 보호(팬·속도 낮춤·비상 종료)로 충분하고, 깨어 있기를 꺼도 식지 않고 작업만 멈추기 때문. 위험은 "잠든 줄 알고 닫아 가방에 넣는" 경우뿐
  - 어느 쪽이든 뚜껑이 닫혀 있었으면(`AppleClamshellState`) 바로 재움(`pmset sleepnow`). 닫힌 뒤에 뚜껑 모드를 풀면 macOS는 스스로 잠들지 않음(2026-10-26 실기 확인: 시간이 끝나 꺼졌는데 3분 넘게 깨어 있었음). 세션이 끝날 때도 같음. 단 클램쉘 모드(전원+외장 모니터)처럼 뚜껑 모드 없이도 깨어 있을 상황이면 재우지 않음
  - 앱 시작 시 `SleepDisabled`가 1이면 끔, 앱 종료 시에도 끔. 동작할 때만 알림
- 감시 작업 (M2 4단계): 뚜껑 모드를 켤 때 `~/Library/LaunchAgents/com.songkyuseob.lantern.watchdog.plist`를 등록하고 끌 때 지움. `~/Library/Application Support/Lantern/랜턴 뚜껑 모드 감시` 스크립트(시스템 설정 "앱 백그라운드 활동"에 실행 파일 이름이 보이므로 `/bin/sh -c`로 하면 "sh"로 보여 이름 있는 파일로 바꿈, `AssociatedBundleIdentifiers`는 ad-hoc 서명에서 효과 없었음)가 5초마다 랜턴 PID가 같은 실행 파일로 살아 있는지 확인(`ps -p PID -o comm=`), 사라지면 `sudo -n pmset -a disablesleep 0` 후 스크립트·등록 파일을 스스로 지움(2026-10-26 Xcode 정지로 실기 확인). `RunAtLoad`라 맥이 강제로 꺼져도 다음 로그인 때 같은 일을 함. 앱 시작 시 남은 것도 정리
- 뚜껑 모드 켜짐 여부는 랜턴이 기억한 값이 아니라 `pmset -g`의 `SleepDisabled`로 판단
- 깨어 있기 = `IOPMAssertion`, 뚜껑 모드 = `pmset -a disablesleep 1` (sudoers에 정확한 명령 3개만, `visudo -c` 검사)
- 자세한 주의사항은 `docs/private/기획.md`의 "주의해야 할 것" (개인 문서)

## 에이전트 감지 (M3, 방향 확정)
- hook은 모델이 아니라 **에이전트 프로그램**(Claude Code `~/.claude/settings.json`, Codex `~/.codex/hooks.json`)에 건다. 터미널·오르카·IDE 등 어디서 실행해도 같은 설정을 읽으므로 실행 도구별 지원은 필요 없다
- 시작 = `UserPromptSubmit`, 끝 = `Stop` (+ `StopFailure`, `SessionEnd`)
- 프로세스 감시만으로는 부족: Claude Code는 작업을 끝내고 입력 대기 중에도 프로세스가 살아 있음
- 참고 구현: 오르카가 같은 방식으로 hook을 설치해 둠 (`~/.orca/agent-hooks/`). 단 오르카 hook은 오르카 환경 변수가 있을 때만 동작하고, 랜턴 hook은 조건 없이 동작해야 함
- 지킬 것: 기존 hook(오르카 등)을 건드리지 않고 추가·제거, 여러 에이전트 동시 실행 시 전부 끝나야 세션 종료, 끝 신호 누락에 대비한 최대 시간 안전장치
- 대상은 내 맥에서 도는 CLI 에이전트만. 클라우드 에이전트는 맥을 깨워 둘 필요가 없음
- 구현 (2026-10-26)
  - 설정 창 "에이전트 연결"에서 에이전트별로 연결·해제. 설정 파일은 키 순서·모양을 지키는 `OrderedJSON`으로 고쳐 랜턴 hook 줄만 더해지고, 해제하면 원본과 바이트까지 같아짐(실제 설정 복사본으로 확인). 고치기 전 파일은 `.lantern-backup`
  - hook 명령은 `~/Library/Application Support/Lantern/lantern-agent-hook`을 실행(없으면 입력만 읽고 성공). 스크립트는 받은 JSON을 `agent-events/`에 파일 하나로 남기고 끝, 출력 없음. 에이전트 프로세스 번호는 SessionStart·UserPromptSubmit 때만 부모를 거슬러 찾음
  - 앱은 폴더를 지켜보다 파일을 쓰인 순서대로 읽고 지움(`AgentMonitor`). 판단은 `AgentSessionTracker`
  - 판단 기준: 끝 신호(Stop·StopFailure·SessionEnd) → 끝. Claude Stop의 `background_tasks`가 남아 있으면 계속. 에이전트 프로세스가 사라지면(시작 시각까지 비교) 끝. 실행 중인 도구·백그라운드 작업이 있으면 신호 없이 최대 3시간, 그 밖에는 30분 동안 신호가 없으면 끝(Esc 중단은 Stop이 안 옴 — Claude 문서 명시). 허락 대기(PermissionRequest)는 30분 기준
  - "에이전트가 끝날 때까지": 모두 끝나고 1분 뒤 해제, 켰는데 에이전트가 30분 동안 시작하지 않으면 해제(`AgentFinishWatch`)
  - Codex는 처음 보는 hook을 `/hooks`에서 승인해야 실행. Claude Code는 폴더 신뢰 전에는 hook 보류. 설정 창에 안내
  - 판단 기준은 상태 카드 도움말과 설정 창에 적어 둠. README(M5)에 옮길 것
  - 창의 "언제까지"는 다섯 칸이 라벨과 한 줄에 안 들어가 라벨을 위로 올림 (Figma v2.5와 다름)

## 0.1.0 점검 뒤 고친 것 (2026-10-29)
- 단축키는 ⌃ 또는 ⌥가 꼭 들어가야 함(⌘ 조합은 앱들이 이미 써서 전역으로 가져가면 막힘). 녹화는 설정 창에서 누른 키만 받고, 설정 창이 키 창에서 벗어나면 취소
- 허락 대기 중이라도, 허락 요청 뒤 시작해 10초 넘게 살아 있는 자식 프로세스가 에이전트 아래에 있으면 허락받고 명령이 도는 중으로 보고 3시간 기준("허락했다" 신호는 따로 오지 않음). 틀리면 더 오래 깨어 있는 쪽
- hook 스크립트는 `plutil`로 이벤트 종류·세션 번호·도구 번호·백그라운드 작업 여부만 뽑아 적음(질문 원문·도구 결과를 디스크에 남기지 않음). 신호 폴더에 2,000개 넘게 쌓이면 더 쓰지 않음
- 감시 작업과 앱 정상 종료 모두, 뚜껑 모드를 끈 뒤 뚜껑이 닫혀 있고 클램쉘(충전기 + 외장 모니터)이 아니면 `pmset sleepnow`. 감시 스크립트는 `ioreg`의 `AppleClamshellState`, `pmset -g batt`, `system_profiler SPDisplaysDataType`(내장이 아닌 화면 수)로 판단. 시스템 종료·재시작 중에는 재우지 않음
- 플로팅 창은 `panel.appearance = darkAqua`로 어두운 테마 고정(라이트 모드 지원은 나중에)
- Apple 실리콘 전용(인텔 미지원). 배포 빌드는 `CODE_SIGN_INJECT_BASE_ENTITLEMENTS = NO`로 `get-task-allow` 제외
- 자동으로 뚜껑 모드를 끄는 경로(세션 종료·안전장치·앱 종료)는 실패해도 관리자 비밀번호 창을 띄우지 않고 알림만 보냄(10분 동안 같은 실패 반복 안 함). 비밀번호 창은 사용자가 직접 끌 때와 앱을 켤 때 남은 걸 끌 때만
- 뚜껑 모드를 켤 때 감시 작업이 launchd에 실제로 올라갔는지(`launchctl print`) 확인하고, 안 되면 뚜껑 모드를 되돌림
- 뚜껑이 닫혀 있으면 내장 화면이 목록에서 빠져도 "뚜껑 있는 맥"으로 봄. 깨어 있는 동안 App Nap을 막음(`beginActivity`)
- 할 일 입력 중인 글은 `PanelState.todoDraft`에 둬서 창이 바뀌어도 남고, 이름 고치던 중이면 창이 바뀔 때 저장
- 할 일 저장 파일을 못 열면 `todos-열지 못함-<시각>.store`로 보관하고 새로 만든 뒤 알림. 그것도 안 되면 메모리 모드 + 알림
- 에이전트 설정 파일이 심볼릭 링크면 원본에 쓰고, 백업은 내용을 복사해 만듦. 응답이 끝난 뒤 늦게 온 도구 끝·서브에이전트 신호는 무시. 백그라운드 작업만 남은 경우 상한 1시간. 신호 폴더가 지워져도 다시 감시, 남은 `.tmp` 정리
- 창 위치: 활성 창의 위쪽 탭 줄을 끌어 옮기고, 놓으면 그 화면(창 가운데가 있는 화면, 밖이면 가장 가까운 화면)의 네 모서리 중 가장 가까운 곳에 붙음(`PanelCorner`). 위쪽 모서리는 아래로, 아래쪽 모서리는 위로 펼쳐짐. 모서리와 화면은 저장하고, 그 화면이 빠지면 주 화면의 같은 모서리. 완전 자유 위치는 걸침·넘침·해상도 변경 예외가 많아 하지 않음. 창 이동은 `setFrame(animate:)`(animator().setFrameOrigin은 창이 옮겨지지 않았음), 끌기 끝은 SwiftUI가 놓칠 수 있어 mouseUp을 직접 지켜봄
- ⌘,는 랜턴 설정 창. 사용자 이름 `ALL`은 권한 설치 거부
- 할 일 동그라미: 테두리만 있는 `Circle().strokeBorder`를 `.plain` 버튼 라벨로 쓰면 선 위만 눌림(0.1.0부터 있던 문제). 라벨에 `frame(20×줄 높이) + contentShape(Rectangle())`을 주고 음수 padding으로 배치는 그대로 둠. 테두리만 있는 아이콘 버튼은 늘 contentShape를 줄 것

- 자동 업데이트(Sparkle)는 0.2.0 이후 검토. 개발자 계정 없이도 EdDSA 키로 가능하지만 키를 잃으면 기존 사용자가 업데이트를 못 받으므로 백업 필수
- 디버그 빌드 전용 조종·화면 저장 명령이 있음(위 "M1 구현에서 정한 세부 동작" 참고)

## 확인한 것
- 2026-10-25 실기 확인: macOS 26에서 `sudo pmset -a disablesleep 1` 상태로 충전기만 연결(외장 모니터 없음)하고 뚜껑을 닫아도 잠들지 않음(디스코드 음성 유지, `pmset -g log`에 잠자기 기록 없음). 확인 후 `0`으로 복구
- 2026-10-26 뚜껑 모드 권한 설치·제거 실기 확인: `/etc/sudoers.d/lantern`이 root:wheel `0440`으로 설치되고, 규칙 밖 명령(`sudo -n pmset -g`)은 "a password is required"로 거부됨
- 2026-10-26 배터리만(충전기·외장 모니터 없음) + 랜턴 뚜껑 모드 스위치로 뚜껑을 닫아도 1분 넘게 음악 유지, 잠자기 기록 없음 → **배터리일 때도 `disablesleep 1`이 동작**. 같은 조건에서 스위치를 켜지 않았을 때는 'Clamshell Sleep'으로 바로 잠듦
- 주의: `sudo -n -l <명령>`은 비밀번호가 필요한 관리자 규칙(`(ALL) ALL`)으로도 통과하므로 "비밀번호 없이 되는지" 판단에 쓸 수 없다. 설치 여부는 `sudo -n -l` 규칙 목록에서 NOPASSWD 명령을 찾아 판단한다(`SudoListing`). sudo는 긴 줄을 화면 폭에 맞춰 끊어 출력하므로 공백·줄바꿈을 합쳐서 읽는다

## 알려진 한계
- MacBook(노치) 화면은 메뉴바 공간이 좁아 왼쪽 아이콘부터 숨겨진다. 랜턴 아이콘이 안 보이면 ⌘를 누른 채 오른쪽으로 끌어 옮기도록 안내. 아이콘이 가려져도 ⌃⌥L로 창을 열 수 있음
- 에이전트 판단은 hook 신호만 보므로 Esc 중단은 최대 30분, 신호 없는 긴 명령은 최대 3시간 뒤에 끝난 것으로 본다. Codex 데스크톱 앱은 엔진 프로세스가 앱 전체와 함께 살아 있어 "프로그램을 닫으면 바로 끝" 규칙은 앱을 종료할 때만 적용
- 배터리 기준·발열 안전장치와 안전장치 알림은 판단 규칙 테스트만 했고 실제 상황으로는 확인하지 못함
- "지금 닫으면" 판단에서 iPad 보조 화면(Sidecar)·AirPlay 화면도 외장 모니터로 잡힐 수 있다. 공식 판별 방법이 없고 추측으로 막으면 진짜 모니터를 놓칠 위험이 커서 일부러 처리하지 않음. 문제가 보고되면 그때 확인
